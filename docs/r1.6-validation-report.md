## Defects found by the real server and the new tests (all fixed)

1. `aaf_app` inherited `anon/authenticated/aaf_service` privileges, so a statement without `SET ROLE` ran with a blend of them. On PostgreSQL 16+ inheritance is fixed per membership *grant*; now NOINHERIT + re-grant, enforced by the start-up guard.
2. **Pool deadlock**: every request held one pooled connection while needing a second for ledger work. Fixed with a dedicated ledger pool.
3. **Authorisation hole** in my new `app_budget_assert`: `NULL OR false` skipped the check, letting an anonymous caller reserve budget in any workspace. NULL-safe now; mutation-tested.
4. **Rollback erased the record of an external effect**: a failing job transaction would have rolled back the `unknown_outcome` marker of a send that could not be rolled back. Execution now records its claim and outcome write-ahead in their own transactions.
5. A timeout on a sending tool was retried (possible double send). Now ambiguous failures of external/financial tools park the approval as `unknown_outcome`, never retried.
6. Budget check was read-then-call (racy). Replaced by atomic reserve/settle/release.
7. AI drafts could echo an attacker-supplied address copied from the incoming email. Any email or URL in an AI draft is now rejected.
8. Login limiter counted successful sign-ins. Now counts failures only.
9. Sentry v11 collects request bodies, cookies, headers, local variables and AI inputs by default. All switched off + scrubber.
10. Harness: cluster-wide role DDL raced across parallel test files; advisory-locked.

## Honest limits of the evidence

- REAL-PG is not Supabase. Supavisor (transaction pooler), PostgREST (must be disabled), GoTrue, extensions and Supabase's role setup are unexercised. The `aaf_app.<ref>` pooler user-name form is untested.
- Cost figures are **estimates** (tokens x configured price). `confirmed_billing` exists in the schema and UI vocabulary but nothing can produce it yet.
- Concurrency tests used a mock model with artificial latency, not provider latency.
- `AAF_RUNTIME_MODE=e2e` is a test-only mode; it is refused on Vercel and makes readiness fail.
- NetworkRadar's read-only enforcement is a patch in a scratch clone. The live deployment still accepts only the full key and OAuth.
